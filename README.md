# そのCO₂のつけは、誰が払う？ ― AR体験（試作版 v0.9）

チームのデモを土台に、作業指示書 第6章の S0〜S8 を当てた実装版です。

## このフォルダの中身
- `index.html` … アプリ本体（デモ＋AR2場面＋体験3-2＋保存先の置き換え＋実証用の切り替え＋審査員用の近道）
- `pilot.html` … 実証（A群 `?g=A`・B群 `?mode=text&g=B`）専用の v1.23 の画面。index.html を A群・B群のURLで開くと、URLの後ろを付けたままここへ切り替わる。実証が終わるまで中身を変えない（不具合の修正だけ。.glb の版番号を上げたときは、ここも合わせる）
- `data/data.json` … 数値と出典（`tools/export_data.py` で作る）
- `models/` … ARのモデル95個（立方体：1日分・1年分・人生分10〜99歳、浸水：0.5m・1.0m・3.0m）
- `tools/` … `export_data.py`（data.json作成）、`make_models.py`（モデル作成）、`hotdays.py`（気象庁の猛暑日データ）、`patch_demo.py`（デモ→index.html の変換）
- `Code.gs` … 回答の保存と「みんなの結果」の集計（Google Apps Script の控え。ファイルはすべて一番上の階層に置く）
- `demo_original.html` … 変換前のデモ（比較用）

## 公開のしかた（GitHub Pages）
1. GitHubで公開リポジトリ `co2-ar` を作り、このフォルダの中身をすべてアップロードする。
2. Settings → Pages → main ブランチを公開。`https://<ユーザー名>.github.io/co2-ar/` で開ける。
3. 審査員用URL：`https://<ユーザー名>.github.io/co2-ar/?start=ar`（または `?mode=judge`）。審査員版（約3分）が開く

## URLの切り替え
- `?mode=judge` … 審査員版（約3分）。はじめの1問 → 体験1の立方体（AR） → 体験4の浸水（AR） → 終わりの1問と選択 → 宣言カード。回答は judge シート
- `?start=ar` … 審査員版を開く（スライドのQRコード用。`?mode=judge` と同じ）
- `?g=A` / `?g=B` … 実証の群を保存データに記録（A群・B群はメールアドレスの入力あり。保存先は pilot シート）
- `?g=J` … 審査員の回答として記録（保存先は judge シート）
- `?mode=text` … 3DとARを隠す（実証のB群用）
- `?fx=off` … v1.21 の新しい見た目と演出をすべて切り、v1.20 の見た目に戻す（実証の当日に不具合が出たときの逃げ道。ほかのパラメータと併用できる。例：`?g=A&fx=off`）
- **`FX_DEFAULT`（index.html の先頭近くの1行）** … 全員の表示をまとめて切り替える。`'full'`（新しい演出をすべて使う）／`'lite'`（重い効果を切る）／`'off'`（v1.20 相当の見た目に戻す）。実証の当日に不具合が出たら、ここを書き換えて push する。URL の `?fx=off`・`?lite=1` はこの設定より優先する（確認用に `?fx=full`・`?fx=lite` も使える）
- `?gfx=high` / `mid` / `low` … 3Dの性能の段階を固定する（確認用。ふだんは自動）
- `?lite=1` … 軽量モード（動く背景・波・1行ずつ現れる演出などを切る）。メモリやCPUが少ない端末、描画の遅い端末では自動で入る

## 回答の保存先（Google Apps Script）
回答は1つのスプレッドシートに、種類ごとにシートを分けて保存する（`Code.gs`）。

| シート | 入る回答 | 補足 |
|---|---|---|
| `responses` | 通常のデモ（group が空欄） | 「みんなの結果」はこのシートだけを集計する |
| `pilot` | 実証のA群・B群（`?g=A`・`?mode=text&g=B`） | 同じ idh・同じ群は上書き。同じ idh で違う群に答えたら行を足し、その idh の全行の dup に「両群」 |
| `judge` | 審査員（`?g=J`） | |

見出し（1行目）：ts, group, ageBand, region, pre, post, ipre, ipost, choices, chosen, sec, cpre, cpost, quiz, idh, dup（idh・dup は最後に追加した列）。idh はメールアドレスを変換した文字列で、アドレスそのものは保存しない。v1.24 から ipre・ipost は空欄（IPCCの質問を外した）、cpre・cpost は「はじめ」「体験のあと」の3択（1取り組んでいる・2今後取り組みたい・3どちらでもない）の答え。

`setupSheets` を実行すると、さらに次のものができる（1行目の列名と列の順番は変えない）。
- 3枚とも1行目を固定し、各列名のセルに日本語の説明（メモ）を付ける。
- `見方` シート：列名・意味・値の読み方の表と、各シートの役割。
- `集計` シート：`pilot` から数式で自動集計（A群・B群それぞれの人数、かかった時間の平均〔分〕、「関わっていると思う」〔4以上〕の割合の前後、企業の商品選択〔1か2〕の割合の前後、クイズの平均点、dup〔両群〕の行の数）。`見方`・`集計` は実行のたびに作り直す。

### Code.gs を更新したときの手順
1. 保存先のスプレッドシートを開き、「拡張機能 → Apps Script」を開く。
2. エディタの `Code.gs` の中身を、このリポジトリの `Code.gs` の中身にすべて置き換えて保存する。
3. 上の関数の選択で `setupSheets` を選び、「実行」を押す（初回は権限の確認が出る。触れるのはこのスプレッドシート1つだけ）。`responses`・`pilot`・`judge` の3枚がそろい、見出しが入る。今の `responses` は、既存の行はそのままで、右端に idh・dup が足される。
4. 「デプロイ → デプロイを管理」で今のデプロイの鉛筆マークを押し、バージョンを「新バージョン」にして「デプロイ」を押す（「新しいデプロイ」は使わない。URL が変わってしまう）。URL は変わらないので、`index.html` の `const API=` はそのままでよい。
5. 動作を確かめる：パラメータなしで1回答 → `responses` に1行。`?g=A` でメールアドレスを入れて1回答 → `pilot` に1行。同じアドレスでもう1回 → 同じ行が上書き。同じアドレスで `?mode=text&g=B` → `pilot` に行が足され、その2行の dup が「両群」。`?g=J` → `judge` に1行。`集計` の人数が増えることも確かめる。
6. 確かめたら、テストで入れた行を各シートから消しておく（実証の前に）。

## 数値を直すとき・ARモデルを作り直すとき
ARモデル（.glb 95個）は `python make_models_v3.py data.json .` で作り直す（numpy と Pillow だけで動く。数値は data.json から計算し、実寸のまま）。作り直したら、index.html のモデルの版番号（`.glb?v=4` の数字）を上げる（iPhone のキャッシュ対策）。

（以下は初期の手順）
`python tools/export_data.py owid-co2-data.csv` → `cd models && python ../tools/make_models.py ../data/data.json`
